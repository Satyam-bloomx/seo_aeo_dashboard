# AuditPro Helper

A small Chrome / Edge extension that lets AuditPro fetch pages **from your browser** for sites you approve.
It helps when a site blocks our server, and it can capture the exact page you have open ("Audit this tab").

What it does and does not do:

- It only talks to the AuditPro app. No other website can use it.
- It has access to **no site** until you allow one, one site at a time, from AuditPro.
- It fetches pages **without your cookies or logins**, so audits show what Google sees.
- If a site shows a bot check, **you** complete it in a normal tab. Only if you turned on "Use verification"
  for that site does the helper reuse that site's bot-check pass cookie (for example Cloudflare's
  `cf_clearance`). Never any other cookie, never for another site.
- It respects robots.txt, loads at most 4 pages at a time per site and slows down when the site is busy.

Use it only for sites you own or have permission to audit.

## Install (team members)

1. In AuditPro, download the helper zip (`auditpro-helper-<version>.zip`).
2. Unzip it to a **permanent** folder, for example `Documents\AuditPro Helper`. Do not delete or move this
   folder later: the browser loads the extension from it.
3. Open `chrome://extensions` (Edge: `edge://extensions`).
4. Turn on **Developer mode** (top right in Chrome, left sidebar in Edge).
5. Click **Load unpacked** and choose the folder that contains `manifest.json`.
6. Pin the helper (puzzle icon → pin) so "Audit this tab" is one click away.
7. Reload the AuditPro tab. AuditPro should now say the helper is connected.

Chrome may show a "Disable developer mode extensions" bubble at start-up; choose to keep it.

## Update

1. Download the new zip from AuditPro.
2. Unzip it **over the same folder** (replace all files).
3. In `chrome://extensions`, click the reload icon on AuditPro Helper (or restart the browser).

Your allowed sites and settings are kept. The extension ID stays the same.

## Google Workspace force-install (optional)

If BloomX uses Google Workspace with managed Chrome, an admin can install the helper for everyone, with no
developer mode and automatic updates:

- **Recommended:** publish the zip as a **private** item in the Chrome Web Store, visible only to the
  BloomX domain. Then Admin console → Devices → Chrome → Apps & extensions → Users & browsers → add by
  ID → *Force install*. Note: the Web Store assigns its own extension ID; AuditPro must accept that ID too.
- **Self-hosted:** pack a `.crx` with the private key from `extension/keys/` (kept by the developer, never
  committed), host it with an update manifest on our domain, and add it in the Admin console as a custom
  app with that update URL. The extension ID stays `phncnhdoeonnplmhjghkdogejgeglmnd`.

Edge can force-install the same way through Microsoft Intune / group policy (`ExtensionInstallForcelist`).

## Using it

- **Allow a site:** AuditPro asks; a helper window opens. Tick "I own this site or have permission to audit
  it", optionally tick "Use verification", click Allow, then confirm Chrome's prompt.
- **Bot check:** AuditPro tells you when a site shows one. Open the page in a normal tab, complete the check
  yourself, then click Continue in AuditPro.
- **Audit this tab:** open the page (log in, accept cookies, open tabs or menus as needed), click the helper
  icon → **Audit this tab**, then go back to AuditPro.
- **Settings:** helper icon → *Settings and allowed sites*: see and remove allowed sites, turn verification
  on or off per site, edit the short list of bot-check cookie names.

If the browser closes or the laptop sleeps mid-audit, the AuditPro server takes over the remaining pages.

## For developers

```
extension/
  manifest.json        MV3 manifest (dev: only http://localhost:3000 can connect)
  helper.config.json   app origins written into the zip's manifest by build.mjs
  build.mjs            node build.mjs  ->  dist/auditpro-helper-<version>.zip
  PROTOCOL.md          app <-> extension messages
  src/background.js    service worker: connection, permissions, fetching, cookies rule, capture store
  src/lib/*.js         pure, unit-tested logic (robots, retries/breaker, challenge, limiter, cookies, runner)
  popup/ options/ permission/   extension pages
  icons/               generated by tools/make-icons.mjs
  tools/               zip/png writer, key generator, extension-ID helper
  test/                node --test extension/test
```

- **Tests:** `node --test extension/test` (Node 18+; no installs).
- **Build:** set `production_origins` in `helper.config.json` (https only), bump `version` in
  `manifest.json`, run `node extension/build.mjs`. `--no-localhost` drops the dev origin for a
  production-only zip; `--check` validates without writing.
- **Load for development:** Load unpacked on the `extension/` folder itself (dev origin only).
- **Extension ID:** fixed by `key` in `manifest.json` → `phncnhdoeonnplmhjghkdogejgeglmnd`. The private key
  is in `extension/keys/` (gitignored); keep a copy in the team password manager. `node tools/make-key.mjs`
  re-derives the public key from it; never regenerate it, or every install gets a new ID.
- **Permissions and why:** `storage` (settings, capture), `cookies` (read allowlisted clearance cookies of
  granted sites only), `declarativeNetRequestWithHostAccess` (attach them to the helper's own requests),
  `webRequest` (observe the helper's own requests for network error codes and redirect hops), `scripting`
  + `activeTab` (Audit this tab), optional host permissions requested per site at runtime.
- **Cookie scoping:** a session rule per host sets the `Cookie` header to `name=value` pairs of allowlisted
  names only, with `regexFilter` for exactly that host, `tabIds: [-1]` and `initiatorDomains: [<extension id>]`,
  so pages, tabs, other extensions and the site's own service worker are never affected. Rules are removed
  when the batch ends or the app disconnects, and on every service-worker start.
